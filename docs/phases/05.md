# Phase 5 — Outfit engine v1 [P0]

Implements the candidate generator + scorer for later ML ranker integration.

1. Skeletons: top+bottom+shoes, dress+shoes, kurta/ethnic_set + bottom + dupatta? + shoes.
2. Hard filters: item available, occasion/formality compatibility, season match, no duplicates.
3. Rule score: body_fit, color_harmony, style_match, occasion_match, season_match, layering, trend, novelty, budget.
4. Diversification: top-N MMR or greedy diversification.
5. Variations: change top/bottom, more casual/trendy, use only wardrobe, add one new item.
6. Add-one-new-item logic for wardrobe gaps.
7. Explanations: top contributing rule features, grounded and template-based.

**API:** POST /outfits/generate {occasion[], style_overrides?, use_only_wardrobe?, add_new_item?, n}; POST /outfits/{id}/variation {type}; POST /outfits/{id}/events {type}; POST /outfits/{id}/save; GET /outfits/saved.

**Acceptance:** demo wardrobe returns ≥3 valid outfit combinations; every outfit has ≥3 factual reasons; use only wardrobe never returns catalog items; deterministic given a seed.
